The solver started as an Excel VBA program and was rebuilt for the web. It solves puzzles with pure logic, the way a human does, and never uses guessing or backtracking. This page explains the idea and the additions made for the web version.

1. Rules and approach

In a nonogram, the numbers next to each row and above each column give the lengths of the runs of black cells in that line, in order, with at least one white cell between runs.

Each cell is unknown, black or white. The solver looks at one line at a time and fixes the cells that are black in every possible arrangement or white in every possible arrangement, then repeats over all rows and columns until nothing changes.

2. Solving a single line (pattern matrix)

The single-line method is explained with figures in the (Japanese) blog post "Nonogram solving algorithm, chapter 1":

  • First pass: list every placement of the clues as a "pattern matrix" and fix the cells common to all patterns (e.g. clues 3 2 1 in 10 cells).
  • Updates: when other lines fix black or white cells, drop the patterns that contradict them and fix the cells common to the remaining patterns.
  • Runs of black cells: narrow down which clue a run of connected black cells can belong to, using the run and the cells at both ends.

3. Speeding it up with matrix operations

"Chapter 2" encodes the states as numbers (white = 0, unknown = 1, black = 2) and filters patterns with matrix products and sums. Helper matrices for invalidating patterns and for finding start and end positions are prepared once and reused, which makes the VBA version fast.

4. The web implementation

  • Forward/backward dynamic programming: instead of listing all patterns, the web version computes, from both ends of the line, how many clues can be placed up to each cell, and derives whether each cell can be black and whether it can be white. The cost is about (cells × clues), so even a 300-cell line is instant.
  • Overall loop: rows and columns are solved alternately; whenever a cell is fixed, the crossing lines are solved again.
  • Responsive UI: solving runs in a Web Worker, so the page never freezes, and a step-by-step mode visualizes the process.

5. Probing

When line logic gets stuck, the solver picks an unknown cell and solves its line twice: once assuming black and once assuming white. Cells that come out the same in both cases are fixed; if one assumption leads to a contradiction, the other one is correct. If two rounds make no progress, the solver stops. Because it never chains guesses, it also tells you whether a puzzle can be solved by logic alone.

6. Generating uniquely solvable puzzles

Turning a photo or QR code straight into black and white usually gives a puzzle without a unique solution. Instead of repairing such puzzles afterwards, the app generates many candidates that look (or mean) the same, measures how much of each one the solver can solve, and picks the best.

  • Photos: over 100 combinations of threshold, 3×3 median smoothing, closing and noise removal are tried. In tests with 30 photo/size cases (30–150 columns), 29 had settings that were uniquely solvable as is, and the last one needed a single cell change.
  • QR codes: the same URL can be encoded with 8 mask patterns, 4 error-correction levels and an optional #1–#15 suffix — all opening the same page. Hundreds of variants are generated, and the chosen one is verified by actually decoding it with jsQR. A solvable QR code was found for all 7 URLs tested.

7. Importing from images with AI

Puzzle images are read by the user's own AI (ChatGPT, Gemini, Claude, …). The dedicated prompt asks for a line-numbered format (R1: 3 1, C1: 2 2), which prevents the AI from skipping or shifting lines. The pasted data is checked automatically: number of lines, whether each line's clues fit, and whether the row and column totals match.
